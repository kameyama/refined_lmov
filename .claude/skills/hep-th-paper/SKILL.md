# hep-th 論文の執筆と推敲

目的は検出の回避ではない。体裁・内容・開示を、分野の研究者が共著者として受け取れる水準にすることである。専門家が「AI が書いた」と判断する理由は、語彙よりも構造と内容にある（ノートのような箇条書き、検証ログ、証明のない断定、薄い引用）。だから語句の置き換えより先に、主張の格付けと構成を直す。

## 守ること（理由つき）

1. 文献を記憶から書かない。架空の引用や誤った arXiv 番号は、arXiv が「LLM の出力を確認していない証拠」として扱い、1 本でも原稿全体の信用を失う。`\cite` のキーは必ず .bib にあり、.bib のエントリは skill `inspire-bibtex` で作ったものにする。確認できない文献は `\cite{TODO-...}` のまま残して報告する。
2. 主張を格上げしない。計算で確かめただけの命題を Proposition・Theorem と呼ばない。「verified」「proved」は、証明か、範囲を明記した再現可能な計算が原稿の中にあるときだけ書く。このリポジトリの原稿では、主張ごとの格付け（導出・計算・予想・仮説）が各テーマの paper/claims.md にあるので、それに従う。
3. 文章を直すときに、式・規約・正規化・量化子・数値を変えない。規約はテーマの conventions.md と原稿の規約の節で固定されている。教科書の標準形に戻さない。式を直す必要があると思ったら、直さずに報告する。
4. 既存の原稿のプリアンブル、文献スタイル、マクロは変えない（このリポジトリの原稿はテーマごとに .claude/rules/ の規則を持つ。そちらが優先する）。JHEP の体裁は新しい原稿か、ユーザーが指示したときだけ使う。
5. AI の使用は Acknowledgments で開示する（arXiv の方針）。開示文は著者が確定するものなので、案を置いて報告する。AI を著者にしない。
6. 最後は著者が全文と全数式を読む。この作業の報告では、著者が自分で確かめるべき箇所（格下げした主張、TODO の引用、直さずに残した疑問点）を挙げる。

## 手順

順に行い、区切りごとに何を変えたかを短く報告する。推敲だけを頼まれた場合は、該当する段階から始める。

1. **主張の分類**：原稿の主張を Theorem / Proposition / Conjecture / 計算による確認（範囲つき）/ Review（既知）に分ける。証明のない主張と、既知の結果を成果のように書いている箇所を挙げる。
2. **構成**：[references/structure.md](references/structure.md) に従って節を組み直す。箇条書き・太字ラベル・囲みを散文にし、検証の記録は付録の表に移す。新しい原稿は [templates/main.tex](templates/main.tex) から始める。
3. **LaTeX**：[references/latex-conventions.md](references/latex-conventions.md) に従う（式番号、句読点、定理環境、引用の書き方）。
4. **文体**：[references/ai-tells.md](references/ai-tells.md) のパターンを取り除く。検査スクリプトを hard が 0 件になるまで回す。soft は 1 件ずつ読んで判断する（機械的に全部消さない）。

   ```bash
   python3 .claude/skills/hep-th-paper/scripts/check_tells.py docs/<テーマ>/paper/en
   ```

5. **引用**：すべての `\cite` を .bib と照合し（スクリプトが未定義のキーと引用数を出す）、新しく足す文献は `inspire-bibtex` で作る。原典・レビュー・最近の関連研究の 3 層がそろっているか、予想に出典があるかを見る。
6. **コンパイルと目視**：テーマの規則にあるコマンドでコンパイルし、ログに `!` と undefined がないことを確かめる。変更したページを画像にして読む。コンパイルが通ることと、ページが論文として読めることは別である。
7. **独立した査読**：サブエージェント `hep-th-referee`（.claude/agents/hep-th-referee.md。原稿だけを読み、書き手の文脈を持たない）に査読させる。指摘を直したら、新しい指摘が出なくなるまで繰り返す。

## 文体の要点（詳細は references/）

- 本文は連続した散文で書く。箇条書きは Discussion の未解決問題など、短い 1 か所まで。
- 単著でも "we"。結果は現在形。断定は証明か明示的な計算があるときだけにし、それ以外は "we conjecture"、"we expect"、"we have checked ... for ..." と書き分ける。
- Abstract は 1 段落で、引用もディスプレイ式も入れない。何を定式化し、何を予想し、どの範囲で確かめたかを書く。
- Introduction は文脈 → 未解決点 → この論文の寄与 → "The paper is organized as follows." の順。
- 節は少なく、中身のあるものにする。節の冒頭の "In this section, we ..." と節末のまとめ文を機械的に付けない。
- 数値・計算による確認は付録の表に置き、本文では範囲を明記して 1〜2 文で述べる。
- ディスプレイ式は文の一部として句読点を付ける。
- 標準的な定義は引用で済ませ、この論文に固有の記法と規約は省かずに書く。
